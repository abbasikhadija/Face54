# M0 — Technical Feasibility report

Date: 2026-10-23. Status: COMPLETE for virtual technical feasibility; physical acceptance remains pending. M1 has not started.

## Acceptance evidence

- React/Vite/TypeScript diagnostic harness, one recorded legal scramble, real cubejs solve in a bundled browser worker, and a Three.js cube with seekable solution boundaries.
- Fixture: `R U2 F' L2 D B2 R' U F2 D' L B U2 R2 F D2`.
- Initial URFDLB facelets: `LFRBUUBDUFFFFRLRLLDRLDFLFBUDUFUDUBDBBRRDLFURLDRUBBLDBR`.
- Observed 22-move solution: `D B2 D2 F2 L F2 B' D' B L F2 B2 L2 D' L2 U' D2 F2 R2 U2 L2 D`.
- Applying that sequence independently solves the original facelets. Actual mesh materials, positions, and normals serialize to the identical state at every boundary. No unresolved virtual state-mapping ambiguity.
- Production Chrome and Edge loaded the worker/assets at `/Face54/`, sought through every solution step, reached the same solved facelets, and returned to the exact initial state. Canvas screenshots differ between scrambled and solved states and match again after reset. Both browser screenshots were visually inspected: the solved view has white top, green front, red right. These observations do not substitute for physical trials.

## Verification commands and results

- `npm test`: 21 tests passed. Includes 18 move conventions and 103 solve states: solved, one move, fixture, and 100 deterministic legal scrambles (seed 540). Each solution boundary cross-checks independent sticker geometry, cubejs cubies, and actual Three.js meshes, covering all 54 stickers.
- `npx vitest run --reporter=verbose --disableConsoleIntercept`: 21 passed, 19.07 s, captured measured timings.
- `npm run build`: TypeScript passed; production build passed (final build 846 ms). Main 747.05 kB / 200.68 kB gzip, worker 19.54 kB. Existing chunk-size warning remains a documented performance risk.
- `npm run test:browser`: final run 2 passed in 23.7 s, installed Chrome 155.0.8059.85 and Edge 155.0.4283.62. No uncaught page errors. Non-root asset and worker loading verified.
- `npm audit --json`: nonzero result; snapshot in npm-audit.json. 42 findings: 12 moderate, 27 high, 3 critical in cubejs's legacy npm tree. This is an open release risk, not a clean security result.
- Scoped `git status --short -- .`: workspace remains untracked within the parent repository. No commit, push, or deployment.

## Decisions and resolved failures

See DECISIONS.md for alternatives, coordinate frames, sources, licenses and trade-offs. cubejs and Three.js use MIT; cubing.js was evaluated but not shipped. No experimental renderer APIs are needed. The product owns a small tested geometry adapter, not a solver algorithm.

The first browser attempt exposed preview base-path configuration and then an upstream cubejs module-worker `this.Cube` crash. Both were fixed: explicit preview base path and a guarded Vite pre-transform selecting cubejs's existing CommonJS branch. The final production regression tests pass. Browser downloads stalled; the suite uses installed Chrome and Edge instead.

## What to understand

A solution is only trustworthy if applying it to the original cube actually solves it. Comparing all 54 renderer stickers after every step also guards against a correct solver attached to a mirrored or incorrectly ordered display.

Workers keep expensive initialization separate from the page, but production bundling can change how old libraries behave. Browser tests caught a compatibility error that Node tests could not.

## Issues and blockers

No blocking M0 solver/renderer mismatch remains. Release concerns: legacy dependency audit findings; version-sensitive cubejs bundler patch; WebGL2 requirement; large main chunk; slow cold initialization. No Firefox, Safari, mobile hardware or real-cube acceptance has been established. User-input validation, full worker lifecycle, and polished UI are deliberately outside this milestone. The repository root is unexpectedly C:/Users/User; establish the intended project repository before future Git/deployment work. No public URL is claimed.
